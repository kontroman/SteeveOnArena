# Проверка UX мобильного управления

## Вывод

Схема подходит для движения и повторной атаки двумя большими пальцами. Для одновременного движения, непрерывного прицеливания и прыжка нужны три пальца. До проверки на физическом телефоне нельзя считать удобство подтверждённым.

Проверены код ввода, CanvasScaler (1920×1080, match=0.5), расположение HUD и автоматические сценарии касаний. Это инженерная оценка, а не тест с игроками.

| Сценарий | Текущее поведение | Оценка |
|---|---|---|
| Движение + атака | Левый палец двигает, правый задаёт направление и автоматически повторяет атаку | Основной бой укладывается в два пальца |
| Прицеливание + прыжок на ходу | Правый палец нужно перенести со стика на прыжок; повторение атак останавливается | Главный конфликт. Непрерывная комбинация требует третьего пальца |
| Щит | Включается нажатием; правый стик после этого задаёт направление защиты | Удерживать третьим пальцем не нужно, но для включения/выключения надо ненадолго отпустить прицел |
| Зелье | Выбор слота, «Выпить», возврат на оружие | Три касания; неудобно в напряжённом бою. При полном здоровье или задержке питья нет объяснения отказа |
| Добыча | Нажать один раз; движение или «Стоп» отменяет | Не требует длительного удержания |
| Плавающий прицел | Центр под пальцем; точка появления произвольная | Расстояние до фиксированных кнопок зависит от места первого касания. Протянуть удерживаемый палец на кнопку недостаточно: нужен новый тап |
| Масштаб камеры | Занятые стиками пальцы исключены из pinch | Прежний жест двумя пальцами в обычном управлении фактически недоступен |

## Исправлено

Невидимая зона мобильных кнопок увеличена с 88×88 до 120×120 единиц Canvas. Видимые кнопки остаются 76×76, как остальные в HUD. Кнопка зелья отодвинута от панели слотов на 10 единиц, чтобы расширенная зона не закрывала первый слот.

## Размер после масштабирования

Расчёт для полного экрана без вырезов, с текущим CanvasScaler. Числа — координаты указанного viewport, **не гарантированные Android dp**. Для WebGL при canvas с devicePixelRatio итог следует пересчитать в CSS-пиксели; для нативной сборки нужна плотность устройства.

| Viewport | Видимая кнопка | Зона до | Зона после |
|---|---:|---:|---:|
| 740×360 | 27.2 | 31.5 | 43.0 |
| 844×390 | 30.3 | 35.1 | 47.8 |
| 915×412 | 32.4 | 37.5 | 51.2 |
| 390×844 | 25.8 | 29.8 | 40.7 |

Android рекомендует минимум 48×48 dp для зоны нажатия и допускает увеличение зоны без увеличения самой графики: [официальные рекомендации](https://developer.android.com/guide/topics/ui/accessibility/apps). На маленьком экране одной фиксированной зоны Canvas недостаточно для гарантии этого размера.

## Следующие решения по управлению

1. Если прыжок — обычное перемещение, допустима короткая пауза в атаке. Если прыжок нужен для уклонения в бою, стоит добавить альтернативный жест прыжка левым пальцем или настраиваемую раскладку под три пальца. Не включать такой жест без обучения: он может вызывать случайные прыжки.
2. Для зелий — быстрый расходник без переключения оружия, с количеством и состоянием задержки. Это отдельное изменение игровой схемы, а не только размера кнопки.
3. Проверить лук на движущейся цели: направление есть, отдельного прицела или линии траектории нет. Нужна оценка точности игроками.

## Проверка на телефоне

В горизонтальном режиме: 60 секунд обходить противника и стрелять; 10 раз прыгнуть во время обхода; 10 раз переключить щит; выпить зелье и вернуться к атаке. Записать промахи по кнопкам, случайные срабатывания, необходимость третьего пальца и потерю направления прицеливания. Повторить на небольшом экране и с другим размером рук.
